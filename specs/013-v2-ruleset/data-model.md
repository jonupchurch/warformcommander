# Phase 1 Data Model: v2 Ruleset

Units: `Bp` = basis points (`10_000` = 1.0), `Fixed` = milli. All new balance magnitudes are ruleset
data (P8); none are literals in engine code.

---

## 1. Ruleset additions

All five tables are `#[serde(default, skip_serializing_if = "…::is_default")]` on `Ruleset`, so the
seed ruleset serializes byte-identically while they hold defaults (R6).

### 1.1 `StanceAggro` — fire-priority offsets

```rust
/// Per-stance fire-priority offset. LOWER is targeted first. Relative within a row:
/// a uniform set of offsets is a no-op (FR-017).
pub struct StanceAggro {
    pub aggressive: i8,   // default -1
    pub neutral:    i8,   // default  0
    pub defensive:  i8,   // default +1
    pub protector:  i8,   // default -1
    pub opportunist: i8,  // default  0
    pub triage:     i8,   // default  0
    pub sustain:    i8,   // default  0
    pub empower:    i8,   // default  0
}
```

The four support/gated stances sit at `0` so they are tier-neutral; their behaviour lives elsewhere.
`Protector` shares Aggressive's tier deliberately — its distinction is cross-zone reach (FR-016), not
a deeper tier, which avoids a fourth tier level that would need its own justification.

### 1.2 `ExecuteMods` — the Opportunist bonus

```rust
pub struct ExecuteMods {
    pub threshold: Bp,   // default 4_000 → hull ≤ 40%
    pub bonus:     Bp,   // default ?     → damage multiplier above BP_ONE
}
```

Both tunable, per the user's explicit note that the 40% figure is open to review. Setting `bonus` to
zero disables the mechanic without a code change — the required "individually reversible" property
(FR-030 applies the same principle to air).

### 1.3 `AblativeMods` — save probability

```rust
pub struct AblativeMods {
    pub save_chance: Bp,   // default 2_000 → 20%
}
```

### 1.4 `MountScale` — per-mount defensive magnitude

```rust
/// Multiplier applied to every defense family's magnitude for a given mount class.
/// The single point of adjustment for rebalancing the defense system (FR-009).
pub struct MountScale {
    pub heavy: Bp, pub light: Bp, pub mech: Bp,
    pub heli: Bp, pub rkt_arty: Bp, pub artillery: Bp, pub support: Bp,
}
```

Heli / RktArty / Artillery carry the lowest factors so their best option still lands below today's
durability (FR-011, SC-008).

### 1.5 `AirRates` — engagement rate tiers

Extends the existing `AirModifiers`. Today it holds `aa_acc_bonus`, `aa_dmg_mult`,
`plink_acc_penalty`, `plink_dmg_mult`, `sam_ground_dmg_mult`, `flak_dmg_mult`, `aa_focus_per_air`. One
field is added:

```rust
/// Damage rate for an Energy-family weapon engaging air — strictly between plink and flak (FR-028).
pub energy_air_dmg_mult: Bp,
```

Ordering invariant, enforced by validation: `plink_dmg_mult < energy_air_dmg_mult < flak_dmg_mult`.

## 2. `DefenseSpec` extension

Today: `mount_class`, `armor_pct_delta`, `shield_delta`, `special_mitigation`, `tradeoff`. One
optional field is added, matching the existing `Option` + skip-if-none convention:

```rust
#[serde(skip_serializing_if = "Option::is_none", default)]
pub ablative_delta: Option<AblativeDelta>,

pub struct AblativeDelta { pub cap: Fixed }
```

`special_mitigation` is retained — Blast Plating keeps working, and it remains the mechanism for
family-targeted splash reduction, which ablative deliberately does *not* provide (FR-006).

### The four families, per mount class

| Family | Grants | Drawback (FR-008) |
|---|---|---|
| **Armor** | `armor_pct_delta` | movement penalty |
| **Shield** | `shield_delta` (cap, regen, delay) | bypassed by penetration |
| **Ablative** | `ablative_delta.cap` | never regenerates |
| **Balanced** | modest `armor_pct_delta` + modest `shield_delta` | none |

Generated by one loop over the seven mount classes applying `MountScale`, mirroring the existing
base-hull loop at [content.rs:749](../../crates/engine/src/content.rs#L749).

**Mech-exclusive fifth entry**: reactive plating, offered only where `mount_class == Mech` (FR-023).

## 4. `Combatant` battle state additions

Current state is listed at [mod.rs:33](../../crates/engine/src/sim/mod.rs#L33). Three fields are
added:

```rust
/// Remaining ablative capacity. Initialised to `stats.ablative_cap`; never regenerates.
pub ablative: Fixed,

/// Damage absorbed per family, indexed by DamageType declaration order.
/// Drives reactive mitigation. Ties resolve to the lowest index (R9).
pub absorbed: [Fixed; 3],
```

`absorbed` is populated for every combatant but only *read* when `stats.reactive` is true — cheap, and
it keeps the update path branch-free.

## 5. State transitions

### 5.1 Ablative pool

```text
                   ┌──────────────┐
   battle start ──▶│  = cap       │
                   └──────┬───────┘
                          │  hit arrives, absorbed = min(incoming, pool)
                          ▼
                   ┌──────────────┐   save roll (save_chance)
                   │  absorbing   ├──── hit ──▶  pool unchanged  ──┐
                   └──────┬───────┘                                │
                          │ miss                                   │
                          ▼                                        │
                   pool -= absorbed  ◀──────────────────────────────┘
                          │
                          ▼  pool reaches 0
                   ┌──────────────┐
                   │  depleted    │  (terminal — no regeneration path)
                   └──────────────┘
```

Invariants:

- `0 ≤ ablative ≤ stats.ablative_cap` at all times.
- Absorption never exceeds the remaining pool; the remainder passes to hull (R4).
- A save preserves capacity but does not increase absorption.
- Depleted is terminal. Unlike `shield`, no tick-based regeneration path exists.

### 5.2 Reactive mitigation (Mech)

```text
battle start ──▶ absorbed = [0, 0, 0]      (neutral — mitigates as Balanced)
                      │
                      │  each hit: absorbed[family] += hull damage taken
                      ▼
              dominant = argmax(absorbed), ties → lowest index
                      │
                      ▼
              incoming of `dominant` mitigated at the reactive rate
```

Invariant: with `absorbed == [0,0,0]` the Mech's mitigation equals its Balanced equivalent exactly, so
reactive plating is never *worse* than neutral at battle start.

### 5.3 Stance tiers (stateless)

No stored state. Tier is read live from `dials.stance` each time a target is selected, because stance
is Plan-B-flippable mid-battle (R5). Narrowing is:

```text
reachable ──▶ pick_row ──▶ [NEW] narrow to min-tier ──▶ pick_unit
                              │
                              ├─ attacker is Aggressive → skip narrowing entirely (FR-014)
                              └─ Protector in an adjacent ground zone that is already
                                 in `reachable` joins the candidate set (FR-016)
```

## 6. Stance role partition

```text
has support_power  ──▶ { Neutral, Triage, Sustain, Empower }
otherwise          ──▶ { Neutral, Aggressive, Defensive, Protector, Opportunist* }

* Opportunist additionally requires the OpportunistStance capability (unchanged).
```

Enforced in the UI as option filtering and in `legality.ts` / engine validation as a check. **Existing
saved armies holding an out-of-role stance remain loadable and degrade to neutral behaviour**
(FR-022) — the role split must not invalidate stored player data.

## 7. Replay contract

`MachineSnapshot` gains one additive field:

```rust
pub ablative: Fixed,
```

`DamageLayer` gains an `Ablative` member so hits against the pool are attributable in the battle
log — **a new enum variant, so R7's deploy-before-re-seed ordering applies to slice 1.**

## 8. TypeScript mirrors

Every addition above is mirrored in `sim/ruleset.ts` and `sim/model.ts` as optional fields with
exported defaults (the `DEFAULT_ENERGY_MODES` pattern), and validated at the trust boundary in
`server/ruleset-validate.ts`:

| Field | Rule |
|---|---|
| `stanceAggro.*` | integer, `-8 ≤ v ≤ 8` |
| `executeMods.threshold` | `0 ≤ v ≤ 10_000` |
| `executeMods.bonus` | finite, `≥ 0` |
| `ablativeMods.saveChance` | `0 ≤ v ≤ 10_000` |
| `mountScale.*` | finite, `> 0` |
| `airMods.energyAirDmgMult` | finite, `≥ 0`, and `plink < energy < flak` |
| `DefenseSpec.ablativeDelta.cap` | finite, `≥ 0` |
